About the Device I Use

I installed Proxmox VE 8.4 on an unused desktop PC. It is an HP M01-F1003nc equipped with an Intel Core i5-10400F processor (Comet Lake, up to 4.3 GHz), an NVIDIA GeForce GTX 1650 Super with 4 GB of VRAM, 8 GB of DDR4 RAM, and a 512 GB SSD. Self-Hosted DNS Server

I self-host AdGuard Home to block advertisements and protect my devices from online threats. It filters malicious domains, improves privacy, and helps keep my entire network safer without relying on third-party DNS services.

I chose AdGuard Home because it provides a clean and intuitive web interface that makes configuration and management straightforward. Its simplicity was an important factor because I wanted a reliable DNS solution without unnecessary complexity.

I configured custom upstream DNS servers to provide fast and secure domain resolution. I also enabled several DNS blocklists to block advertisements, phishing attempts, tracking services, and other malicious websites.

This setup helps protect every device on my network while also improving browsing speed and privacy.

Secure Tunnel to My Local Network

Twingate is a modern and secure remote access solution that provides an alternative to traditional VPNs. It allows users to securely connect to private resources such as internal servers, applications, and databases without exposing the entire network.

Twingate uses a zero-trust approach, meaning that each user or device receives access only to the resources they actually need.

To enable secure remote access with Twingate, I set up a dedicated virtual machine on my Proxmox server. The VM runs a Docker container with the Twingate Connector, which acts as a secure gateway between Twingate and my private network.

After creating the VM, I installed Docker and deployed the Twingate Connector using the configuration provided in the Twingate administration panel. The setup was simple and efficient. I registered the Connector with my Twingate network, copied the automatically generated Docker run command, and launched the container.

Once running, the Connector established a secure, encrypted connection to Twingate's cloud infrastructure. This allows authorized users to access my TrueNAS server on ports 137-139 and 445 (SMB).

As the administrator, I can also manage internal services such as AdGuard Home, TrueNAS, and Proxmox web interfaces without exposing any part of my local network directly to the public internet.

Exploring Tails OS

Tails (The Amnesic Incognito Live System) is a security-focused, Debian-based Linux distribution designed to protect privacy and anonymity.

I discovered Tails while researching privacy-focused Linux systems. It runs entirely from a USB drive or DVD and primarily uses the computer's RAM, leaving no trace on the host system by default. This makes it useful for privacy-conscious browsing and other activities where minimizing local traces is important.

One of Tails' core features is its integration with the Tor network. The operating system includes the Tor Browser, which anonymizes internet traffic by routing it through a volunteer-operated network of relays. This makes it significantly more difficult for websites and other observers to determine your original IP address.

Tails also provides an "amnesic" environment, meaning that data is not normally retained between sessions unless you explicitly choose to save it. However, Tails supports optional encrypted persistent storage.

Persistent storage allows you to securely save selected files, system settings, additional software, and personal data on the USB drive. The storage is protected and can only be accessed after entering the appropriate passphrase during startup.

In my personal setup, I have enabled persistent storage to install and explore various penetration testing, social engineering, and cybersecurity tools. Tails provides an isolated environment for learning about digital privacy, anonymity, and ethical security practices without modifying the host operating system.

This project was part of my maturita exam. It focused on installing and configuring a Linux server for hosting a website. I used a ZimaBoard, a compact single-board computer designed for various server and home-lab applications.

The project included installing and configuring Apache2, setting up remote access through SSH, securing the server with the UFW firewall, and using PHPMailer to send emails securely.

The main goal was to configure a Linux web server and create a simple website using PHP as the backend. Working with a physical server gave me a better understanding of hardware, server administration, networking, and system security.

Compared to conventional web hosting, running my own physical server gave me much greater control over the system's configuration and security.
